What can .ebextensions define?

These are configuration files, not an extension marketplace. Put YAML/JSON .config files in your source bundle's .ebextensions/ folder. They configure Beanstalk Standard environments.

ResourcesAny CloudFormation-supported resource typeElastiCache, SQS, SNS, alarms, IAM roles or RDS; creation needs appropriate permissions

Install ≠ provision. packages installs software on the EC2 instances. Resources → AWS::ElastiCache::CacheCluster creates a separate managed cache in the environment's CloudFormation stack.

Lifecycle. A stack-owned cache normally disappears when the environment is terminated. CloudFormation DeletionPolicy: Retain or supported snapshot policies can change cleanup. Referencing an external cache/database does not transfer ownership; resources created separately by a script are not automatically tracked by the stack. Keep durable/shared data in a separate stack.

Modern Linux. Use application manifests such as requirements.txt / package.json for runtime dependencies, and platform hooks (.platform/hooks/prebuild, predeploy, postdeploy) for custom scripts. Match packages and service management to the OS/runtime. container_commands refers to app staging; it does not require Docker.
