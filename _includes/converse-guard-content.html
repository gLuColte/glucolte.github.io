guardContent — scope which input the guardrail checks

Converse API → Content Blocks → Guardrail Scoping

A single Converse message can mix blocks. With guardContent, scope the HIGH content filters to the user question; trusted passages in plain text still reach the model without those checks.

Converse Message
├─ Plain text: trusted report
│  "Attacker exploited..."
│  → Model (skip filters)
│
└─ guardContent: user question
   "How do I mitigate this?"
   → Guardrail (HIGH)
   → Model if allowed
Exam Pattern

Trusted context causes false positives + user input must still be checked + same strength + less text to check → use guardContent.

Common trap: HIGH → LOW/NONE also weakens protection for the user's question.

Remember: scope evaluation; keep the guardrail strong. Wrap every user question that needs checking. AWS Converse guardrail scoping.
