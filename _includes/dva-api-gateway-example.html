Follow one request: GET /GetOrder

Two stages of one REST API. The URL chooses the stage; the API key identifies the consuming application. This is a local illustration, not a live AWS call.

Application data plane · caller → API Gateway → Lambda 
GET https://a1b2c3d4e5.execute-api.ap-southeast-2.amazonaws.com/prod/GetOrder?orderId=o-42
Authorization: <Cognito access JWT>
x-api-key: <PartnerApp API key>

200 OK · prod → deployment d1 → orders:prod (version 1)

  1. URL → stage → deployment

    /prod selects prod, pointing to API deployment d1. /GetOrder is the resource; GET is the method.

  2. Who is calling?

    The Cognito authorizer validates the access token and required orders/read scope. The API key separately identifies PartnerApp for its usage plan.

  3. Validate input & apply usage limits

    Require orderId and an API key on this method. PartnerDemo targets 10 requests/s, burst 20, and 1,000/day per key across prod + beta.

  4. Cache → mapping → integration

    On a cache miss, a non-proxy VTL mapping creates the Lambda JSON below. The integration uses stage variable functionAlias=prod to invoke orders:prod.

  5. Backend → response

    Lambda checks that user-42 may read order o-42, loads the order, and returns 200. Integration/method response settings expose that result to the caller.

Mapped Lambda input · custom/non-proxy integration
{
  "orderId": "o-42",
  "environment": "prod",
  "callerSub": "user-42"
}
Caller receives
HTTP 200
{
  "orderId": "o-42",
  "status": "READY",
  "apiVersion": "v1"
}

prod: GET caching enabled, TTL 60 s, cache keys = Authorization + orderId. beta: cache disabled. A cache hit skips Lambda; it must never cross user/tenant boundaries.

Developer control plane. Deploy an API snapshot; point a stage to it; configure its variables, cache and logs. Here the integration target is orders:${stageVariables.functionAlias} (shorthand). prod → Lambda alias prod/v1; beta → alias beta/v2. Grant API Gateway permission to invoke those aliases. A stage, API deployment, and Lambda version are separate objects; stages do not automatically isolate code or data.

Custom domain. https://api.example.com/orders/GetOrder can map orders → this API's prod stage. The mapping selects the stage even when its name is absent from the public URL.

Evidence. Stage access/execution logs, CloudWatch metrics and enabled traces explain requests. CloudTrail records API configuration changes. The numbered checkpoints explain responsibilities, not a guaranteed internal execution order.
