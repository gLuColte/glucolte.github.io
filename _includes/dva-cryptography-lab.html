AWS KMS — small secret vs large file

Analogy: KMS is a key vault. It can lock a small item for you, or protect the key you use to lock a large file yourself.

Small data · up to 4,096 bytes

KMS encrypts/decrypts the data with a symmetric KMS key that stays in KMS.

# Conceptual calls
blob = kms.Encrypt(secret, KeyId=K)
secret = kms.Decrypt(blob)
Large file · e.g. 111 GB

Client encrypts the file. KMS protects its data key.

# Conceptual envelope encryption
D, wrapped_D = kms.GenerateDataKey(K)
encrypted_file = AES_encrypt(file, D)
save(encrypted_file, wrapped_D, metadata)
clear_from_memory(D)

Another authorised client: D = kms.Decrypt(wrapped_D) → file = AES_decrypt(encrypted_file, D) → clear D.

Remember: D and wrapped_D are two forms of one data key. Keep plaintext D temporarily in client memory; store the encrypted key beside the ciphertext. KMS retains K, not both returned data-key copies. The second client still needs storage and KMS permissions.
